### 本轮发现的引擎缺口（f41cc53 已修）

1. **`{{page}}` 未替换**：parseSearchUrl/resolveSearchUrl 只换 `{{key}}` → 补 `{{page}}`（丁丁/猫眼报"页码必须是整数"）
2. **`$..` 递归下降缺失**：jsonGet 前缀剥离把 `$..list` 吞成 `list`；jsonTokens 不认识 `..` → 新增 jsonFindDeep（阅友/疯读/南极 bookUrl 依赖）
3. **JSON `##` 后缀只支持 3 段**：legado 2 段 `body##正则` = 删除 → splitReplaceSuffix 补 2 段分支
4. **`&&` 拆分误切 @js 块**：extractList 的 && 合并只屏蔽 `<js>`，没屏蔽 `@js:`（代码里的 && 运算符被切碎 → SyntaxError）→ 补 `@js:[\s\S]*$` 屏蔽
5. **无 `$` 前缀 JSON 路径**：`data.state[*]` 被 parseRule 当 CSS → 识别 `[*]`/`[a:b]`/`[?(...)]` 括号形式为 JSON（`[0]`/`[-1]` 与 CSS 下标歧义，不触发）
6. **`{{...}}` 模板缺失**：bookUrl/kind 的 `https://x/{{$.novelId}}` 字面+模板规则无法求值 → extractFromJsonObject 补模板替换（内层 `##` 只作用于模板内）
7. **@js bookList 返回 JSON.stringify 字符串项**：番茄 push 字符串 → 逐项 JSON.parse 回对象

### 源规则修正（DB 直接更新）

- **丁丁小说**：page=1 被 API 永久限频（4011"请勿频繁操作"），page≥2 正常 → searchUrl 改 `@js:'/search?page=' + (page + 1) + '&keyword=' + java.encodeURI(key)`（应用第 1 页→API 第 2 页）
- **南极小说**：书名/作者在 `state[].items[]` 层 → bookList 改 `data.state[*].items[*]`（引擎已支持无 `$` 路径）

做法（沿用方法论）：
1. 抓真实 API 响应 → 分析结构
2. 定位缺口：引擎语法 or 源规则过时（书源 JSON 可本地修正）
3. 引擎缺口 → 实现+测试+独立提交；源规则问题 → 记录并修正源
4. 修复后单源真实验证（通用词 + 斗破苍穹）
