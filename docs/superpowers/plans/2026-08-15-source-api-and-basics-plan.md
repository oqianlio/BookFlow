## 阶段 S2-J：修复 JSON API 类书源（逐个，真实源驱动）

| 源 | 规则特征 | 疑似缺口 |
|---|---|---|
| 丁丁小说 | `$.data[0]`，`page={{page}}` | API 报"页码必须是整数"——page 参数格式/起始值 |
| 南极小说 | `data.state[*][0]`（腾讯 API） | 响应是模块聚合结构，规则需逐层剥 |
| 猫眼看书 | `$.data[*][0]` | 类似聚合结构 |
| 疯读极速 | `$..books[*][0]`，带 _token | token 可能过期/参数 |
| 阅友小说 | `$..list[*][0]` | 响应 count:4479 有数据，规则路径可能错 |
| 番茄聚合API | @js bookList（tab_type/短剧） | js 复杂，需验证 TYPE()/结构分支 |

做法（沿用方法论）：
1. 抓真实 API 响应 → 分析结构
2. 定位缺口：引擎语法 or 源规则过时（书源 JSON 可本地修正）
3. 引擎缺口 → 实现+测试+独立提交；源规则问题 → 记录并修正源
4. 修复后单源真实验证（通用词 + 斗破苍穹）
