## 迭代目标（用户确认）

> 让「能搜到就能读」成为默认：常用书源 搜索→目录→正文 全链路可用；

每个目标都有**完成标准**（可衡量）与**验证方式**，完成才算数。

## 目标 1：建立真实健康基线

**完成标准**：丁丁限流恢复后，用节流代码（域名分组串行）全量重跑 96 个启用源，产出三档数据：
- 搜索可用率：X / 96
- 目录可用率：Y / 有目录规则数（失败分类：network / empty）
- 正文可用率：Z / 有正文规则数（失败分类：network / empty）

**验证**：报告数字 + 失败源完整清单（记录到本文件"结果"节）。
**预估**：1 小时。

## 目标 2：常用源全链路 100% 达标

**完成标准**：错层、丁丁、阅友、南极、番茄、疯读 6 个常用源，搜索→目录→正文全部可用（正文 ≥200 字符）。

**方法**（lessons 3.39 流程）：
1. 失败源先单源单次请求复核（排除限流干扰）
2. 判断原因：限流（等恢复）/ 反爬（补 header/cookie/Referer）/ 规则缺口（修规则）
3. 修复后单源复验 3 环节
4. 每源一条验证记录

**验证**：每源 3 环节验证记录写入本文件。
**预估**：2-3 小时。

## 目标 3：全链路检测 GUI（把测试脚本变成产品能力）

**完成标准**：书源管理新增「全链路检测」入口：
- 复用 fullChainHealth 节流逻辑（域名分组串行 + 200ms 间隔）
- 结果按 搜索失败 / 目录失败 / 正文失败 分类展示（含失败原因）
- 支持勾选批量禁用

**前置确认**：现有「批量验证」是搜索级（sourceVerify），全链路检测是目录/正文级——两者并存不冲突。

**验证**：单元测试 + 真机操作一遍（发现 1 个真实失效源并禁用）。
**预估**：2-3 小时。

## 目标 4（穿插）：悬浮工具栏体验闭环
