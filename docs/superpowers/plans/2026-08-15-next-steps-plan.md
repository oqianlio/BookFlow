## 一、项目现状总结

### 1. 产品定位

枕书：Tauri 2 + React 19 + TypeScript + Rust 的桌面阅读器。
双引擎：本地阅读（EPUB/PDF/MD/TXT，tantivy 全文索引）+
legado 书源生态（搜索/探索/目录/正文/换源/缓存）。

| 模块 | 能力 |
|---|---|

## 二、下一步开发规划

### 阶段 S1：全链路真实源验证（从"能搜到"到"能读完"）

现状：健康检查只验证"搜索"环节；搜索可用的源在**目录/正文环节的真实失败率
未知**（本次 2.1 实测目录/正文检测会大量网络失败，但规则级失败未分类）。

1. **全链路健康检查**：扩展检查脚本，对搜索可用源依次验证
   搜索 → 目录提取 → 正文提取，输出各环节失败率与失败分类
   （网络 vs 规则 vs 站内无）。
2. **根据分类修复**：目录/正文环节的规则缺口（见 S2）。

验收：输出"搜索可用 X / 目录可用 Y / 正文可用 Z"统计，修复 Top 规则缺口。

### 阶段 S2：规则引擎补齐（原版对齐，真实源驱动）

按 S1 数据排序，候选：

1. **目录分页（ruleToc.nextTocUrl）**：长篇书目录分页时当前只取第一页，
   阅读长书看不到后续章节；需支持"下一页"循环（防死循环、防重复）。
2. **正文下一页（ruleContent.nextContentUrl）**：部分源正文分页。
3. **正文清洗（ruleContent.replace / purifyContent）**：正文中的广告/脚本
   过滤规则（已有 purifyContent，验证真实源覆盖）。
4. **`@get:`/`@put:`/`{{}}` 变量语法**：原版 ruleParam（putMap 存取、{{}} 内嵌
   规则求值）——jsBlock 之外的静态规则变量。
5. **探索（exploreUrl/ruleExplore）**：发现页分类、筛选规则的真实源验证。

验收：每项独立提交；健康检查/单源调试验证；测试全绿。

### 阶段 S3：阅读体验补全（用户可见价值）

1. **章节缓存管理 UI**：清除缓存、缓存大小统计（r7 后续项）。
2. **本地书统计扩展**：阅读时长/次数（r10 后续项，books 表扩展）。
3. **书架分组/多选批量操作**（r5 后续项）：书架内分组、多选移入移出。
4. **TTS 朗读**（预留接口的落地）。

### 阶段 S4：生态与管理扩展

1. **订阅自动定时刷新**（source-export-subscription 后续项）。
2. **RSS 增强**：已读状态、OPML 导入导出（r11 后续项）。
3. **可视化书源编辑**（规则编辑器，工作量大，排最后）。

### 优先级建议

- 先 S1（1 个迭代）：建立全链路基线，避免"能搜到但读不了"的黑洞。
- 再 S2（2-3 个迭代）：按 S1 数据逐个修规则缺口。
- S3 按用户反馈穿插；S4 排后。
