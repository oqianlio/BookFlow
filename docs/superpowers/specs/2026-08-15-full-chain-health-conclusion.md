# 全链路书源健康检查结论（S1）

日期：2026-08-15
状态：已批准

## 一、检查方法

`src/services/fullChainHealth.test.ts`（SOURCE_HEALTH=1 门控）：
对启用书源依次验证 搜索 → 目录（ruleToc）→ 正文（ruleContent），
输出各环节可用率与失败分类（network / empty / norule）。
第二轮按 chunk 实时打印逐源结果（个别源 jsBlock 卡死时也能收集数据）。

## 二、数据（274 源，关键词"我的"）

- **搜索可用：68/274**
- **目录环节**：34 个有规则源 → 12 可用（35%）、22 失败
  - network 9：超时/403/不可达（非规则问题）
  - empty 13：目录提取为空 —— 抽查 365小说网 为 TXT 下载站（书页无阅读
    目录，`dl > dd` 不匹配）；克苏鲁公社 chapterList="body" 特殊写法；
    多为站内无阅读页或源规则过时，**非引擎语法缺口**
- **正文环节**：10 个有规则源 → 8 可用（80%）、2 失败（正文过短 0 字符：
  笔趣阁⓪、得奇小说 —— 正文规则含 js 处理，疑似需要 java.getString）
- **搬山人小说网**：jsBlock 同步执行卡死（疑似灾难性正则/死循环），
  卡住整个检测 chunk —— 同步 JS 无法超时中断，属引擎已知限制

## 三、结论与 S2 优先级（数据驱动调整）

1. **P0 nextTocUrl 目录分页**：36小说网等分页目录源当前只取第一页
   （36小说网目录"4 章"实为首页 4 条），长篇书读不完 —— 引擎级缺口。
2. **P1 java.getString(rule, html)**：真实源（正文 js）使用，缺失导致
   正文提取失败。
3. **P2 正文过短保护**：笔趣阁⓪ 等正文规则失败分类与提示。
4. **P3 jsBlock 卡死防护**：检测脚本/UI 层面对 jsBlock 输入截断或隔离
   （同步 JS 无法超时，记录为已知限制）。

## 四、方法论收获

- 全链路检查发现"搜索可用"与"能读完"差距巨大（68 vs ~12）；
  单环节检查会高估可用性。
- 失败分类（network/empty）避免把站点问题误判为引擎缺口。
- 逐源实时打印 + allSettled：卡住也有数据，可定位元凶源。
